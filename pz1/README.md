Task Management System

Базова архітектура системи керування завданнями, побудована за принципами Clean Architecture. Логіка розділена на окремі шари, щоб відділити бізнес-правила від баз даних та зовнішніх інтерфейсів.

Опис шарів проєкту:

1. domain — основні сутності системи (User, Project, Task). Тут описані базові моделі даних та методи роботи з ними, які не залежать від сторонніх бібліотек чи БД.

2. application — бізнес-логіка та сценарії використання (Use Cases). Містить класи CreateTask, AssignTask та CompleteTask, які відповідають за конкретні дії над сутностями з доменного шару.

3. interfaces — шар адаптерів та вхідних точок програми. Призначений для розміщення маршрутів API чи CLI-інтерфейсу, які приймають запити та викликають потрібні юзкейси.

4. infrastructure — технічна реалізація та робота із зовнішніми ресурсами: підключення до бази даних, ORM-моделі, реалізація патерну Repository тощо.

5. tests — модульні тести (unittest) для ізольованої перевірки роботи сутностей та бізнес-сценаріїв.

Запуск тесту:
Перевірити роботу логіки можна з кореневої папки проєкту стандартною командою в терміналі:
python -m unittest discover tests
